# WSCM 服务端多重订阅聚合修改方案

本文档给出一份按当前 WSCM 代码可落地的服务端多重订阅修复方案。目标是解决多个远端 WebSocket session 订阅相同本地事件时，服务端重复调用本地 `EventHub.Subscribe(...)` 导致的订阅风暴问题。

当前问题发生在：

- `WebSocketCommunicationModule/Server/WebSocketSession.cs`
- `SubscribeAsync(SubscribeMessage message, CancellationToken cancellationToken)`

当前实现中，每个 session 收到一次 `SubscribeMessage` 都会创建一个本地 EventHub 订阅：

```csharp
localToken = eventHub.Subscribe(localFilter, eventArg => _ = SendLocalEventAsync(eventArg));
```

如果 1000 个远端客户端订阅相同的 `Source + EventType`，服务端会创建 1000 个本地 EventHub 订阅。修复方案是引入服务端全局订阅聚合管理器，将相同本地过滤条件的远端订阅聚合成一个本地 EventHub 订阅。

## 1. 修改目标

实现后应满足：

1. 多个 session 订阅相同本地事件时，本地 `EventHub.Subscribe(...)` 只调用一次。
2. 本地事件触发后，管理器把事件 fan-out 给所有远端订阅者。
3. 任意远端 token 取消订阅时，移除该 token 对应的全部聚合订阅。
4. 最后一个远端订阅者移除后，才调用本地 `EventHub.Unsubscribe(...)`。
5. session 断开或 Dispose 时，清理该 session 下所有远端订阅。
6. 同一个 session 中同一个 `TokenId` 重复订阅时，先清理旧订阅，再加入新订阅。
7. 不改变客户端侧订阅流程，不影响 `WebSocketCommunicationModule` 作为客户端连接远端的逻辑。
8. **必须防止 session 断开与订阅登记之间的竞态导致 manager 持有已断开 session。**
9. **必须限制 fan-out 并发度，避免热点事件触发时制造 WebSocket 发送风暴。**
10. **必须保证 `EventHub.Subscribe/Unsubscribe` 异常不会在 manager 内留下脏聚合状态。**

## 2. 总体设计

新增一个服务端全局对象：

```text
WebSocketSubscriptionManager
```

由 `WebSocketEventServer` 持有，并传入每个 `WebSocketSession`。`WebSocketSession` 不再直接调用 `eventHub.Subscribe(...)`，而是委托给 manager。

修改后的服务端链路：

```text
Remote Client
  -> SubscribeMessage(tokenId, filter)

WebSocketSession
  -> subscriptionManager.Subscribe(session, tokenId, filter)
  <- SubscribeAck

WebSocketSubscriptionManager
  -> 按本地订阅 key 查找聚合项
  -> 不存在则创建一个本地 EventHub.Subscribe
  -> 将 (sessionId, tokenId) 加入一个或多个聚合项 subscribers

Local EventHub.Publish
  -> 聚合订阅回调
  -> subscriptionManager.FanOutAsync(key, eventArg)
  -> session.SendRemoteEventAsync(tokenId, eventArg)
```

## 4. 核心模型

### 4.1 ServerSubscriptionKey

用于表示一个本地 EventHub 订阅的聚合 key。

当前服务端收到远端 filter 后会执行：

```csharp
var localFilter = new EventFilter(message.Filter)
{
    Host = string.Empty,
};
```

因此聚合 key 不应使用远端传入的 `Host`。第一版建议按每条 `SourcesAndTypes` 拆分聚合：

```csharp
internal readonly record struct ServerSubscriptionKey(
    string Source,
    string EventType,
    int PerformanceLevel);
```

说明：

- `Source` 和 `EventType` 是本地事件匹配的核心字段。
- `PerformanceLevel` 如果会影响 EventHub 行为，应纳入 key。
- `Host` 在服务端本地订阅中固定为空，不纳入 key。

如果后续确认 `EventFilter` 还有其他影响匹配的字段，也必须加入 key。

### 4.2 RemoteSubscriptionKey

不能只用远端 `TokenId` 做全局反向索引。不同 session 理论上可能发送相同 `Guid`，所以反向 key 应包含 session。

```csharp
internal readonly record struct RemoteSubscriptionKey(
    Guid SessionId,
    Guid RemoteTokenId);
```

用途：

- 快速查找某个 session 的某个远端 token 当前属于哪些聚合 key。
- 支持同一个 token 重复订阅时先清理旧订阅。
- 避免跨 session token 冲突。

### 4.3 RemoteSubscriber

表示一个远端订阅者。

```csharp
internal sealed class RemoteSubscriber
{
    public RemoteSubscriber(Guid sessionId, Guid remoteTokenId, WebSocketSession session)
    {
        SessionId = sessionId;
        RemoteTokenId = remoteTokenId;
        Session = session;
    }

    public Guid SessionId { get; }

    public Guid RemoteTokenId { get; }

    public WebSocketSession Session { get; }
}
```

注意：这里直接持有 `WebSocketSession`，用于事件触发时发送。**由于这是强引用，session Dispose 时必须主动从 manager 中移除该 session 的所有 token，并且 manager 自身 Dispose 时也要兜底清理全部聚合订阅，避免内存泄漏。**

### 4.4 AggregatedServerSubscription

表示一个聚合订阅。

```csharp
internal sealed class AggregatedServerSubscription
{
    public Token? LocalToken { get; set; }

    public EventFilter LocalFilter { get; init; } = new();

    public ConcurrentDictionary<RemoteSubscriptionKey, RemoteSubscriber> Subscribers { get; } = new();
}
```

`LocalToken` 是本地 `eventHub.Subscribe(...)` 返回值，用于最后取消本地订阅。

## 5. WebSocketSubscriptionManager 设计

核心字段：

```csharp
internal sealed class WebSocketSubscriptionManager : IDisposable
{
    private readonly EventHub eventHub;

    private readonly ConcurrentDictionary<ServerSubscriptionKey, AggregatedServerSubscription> aggregatedSubscriptions = new();

    private readonly ConcurrentDictionary<RemoteSubscriptionKey, ServerSubscriptionKey[]> remoteIndex = new();

    private readonly object syncRoot = new();

    private readonly int maxFanOutConcurrency;

    private bool disposed;
}
```

字段含义：

- `aggregatedSubscriptions`：本地订阅 key 到聚合项。
- `remoteIndex`：远端 `(SessionId, TokenId)` 到聚合 key 集合的反向索引。一个远端 token 的 `EventFilter.SourcesAndTypes` 可能包含多条规则，语义是命中任意一条就触发，因此同一个远端 token 必须能映射到多个聚合 key。
- `syncRoot`：保护创建、移除本地 EventHub 订阅的临界区。
- `maxFanOutConcurrency`：fan-out 发送并发上限。**不要对所有 subscriber 直接 `Task.WhenAll`，否则热点事件会产生瞬时网络发送风暴。**

第一版用单锁即可，逻辑简单可靠。后续如果锁竞争明显，再改成 per-key lock。**锁内允许调用当前纯内存的 `EventHub.Subscribe/Unsubscribe`，但必须对异常做回滚，不能留下没有 `LocalToken` 或 subscriber 状态不完整的聚合项。**

## 6. Manager.Subscribe 流程

方法建议：

```csharp
public void Subscribe(WebSocketSession session, Guid remoteTokenId, EventFilter remoteFilter)
```

处理步骤：

1. 校验 `session` 和 `remoteFilter`。
2. 校验 `remoteFilter.SourcesAndTypes` 非空。
3. 遍历 `remoteFilter.SourcesAndTypes`，按每条 `Source + EventType` 拆分成一个聚合订阅 key。多条 `SourcesAndTypes` 的语义是 OR，命中任意一条都应触发远端 token。
4. 对同一个 `(session.Id, remoteTokenId)` 先执行 `Unsubscribe(...)`，清理旧订阅。
5. 为每条 `SourcesAndTypes` 构造只包含该条规则的 `localFilter`，并清空 `Host`。
6. 为每条规则构造 `ServerSubscriptionKey`。
7. 如果某个聚合项不存在，则创建 `AggregatedServerSubscription`，并调用一次本地 `eventHub.Subscribe(...)`。
8. 把同一个 `RemoteSubscriber` 加入所有对应聚合项。
9. 将 `remoteIndex[remoteKey]` 写为本次订阅生成的全部 `ServerSubscriptionKey[]`。

支持多条 `SourcesAndTypes` 的伪代码：

```csharp
public void Subscribe(WebSocketSession session, Guid remoteTokenId, EventFilter remoteFilter)
{
    ThrowIfDisposed();

    if (remoteFilter.SourcesAndTypes.Count == 0)
    {
        throw new ArgumentException("Filter must contain at least one source/type.", nameof(remoteFilter));
    }

    var remoteKey = new RemoteSubscriptionKey(session.Id, remoteTokenId);
    var distinctSourceAndTypes = remoteFilter.SourcesAndTypes
        .Select(sourceAndType => new
        {
            sourceAndType.Source,
            sourceAndType.EventType,
            remoteFilter.PerformanceLevel,
            Value = sourceAndType,
        })
        .DistinctBy(item => new ServerSubscriptionKey(
            item.Source,
            item.EventType,
            item.PerformanceLevel))
        .ToArray();

    lock (syncRoot)
    {
        UnsubscribeCore(remoteKey);

        var subscriber = new RemoteSubscriber(session.Id, remoteTokenId, session);
        var keys = new List<ServerSubscriptionKey>();

        try
        {
            foreach (var item in distinctSourceAndTypes)
            {
                var key = new ServerSubscriptionKey(
                    item.Source,
                    item.EventType,
                    item.PerformanceLevel);

                if (!aggregatedSubscriptions.TryGetValue(key, out var aggregated))
                {
                    var localFilter = CreateSingleSourceLocalFilter(remoteFilter, item.Value);

                    aggregated = new AggregatedServerSubscription
                    {
                        LocalFilter = localFilter,
                    };

                    try
                    {
                        aggregated.LocalToken = eventHub.Subscribe(
                            localFilter,
                            eventArg => _ = FanOutAsync(key, eventArg));
                    }
                    catch
                    {
                        // **重点：Subscribe 失败时不能把没有 LocalToken 的聚合项放入字典。**
                        throw;
                    }

                    aggregatedSubscriptions[key] = aggregated;
                }

                aggregated.Subscribers[remoteKey] = subscriber;
                keys.Add(key);
            }

            remoteIndex[remoteKey] = keys.Distinct().ToArray();
        }
        catch
        {
            // **重点：多 SourcesAndTypes 订阅可能已加入部分聚合项，失败时必须回滚。**
            RemoveSubscriberFromKeys(remoteKey, keys);
            throw;
        }
    }
}
```

`CreateSingleSourceLocalFilter(...)` 的目标是把远端 filter 拆成只包含一条 `SourcesAndTypes` 的本地 filter：

```csharp
private static EventFilter CreateSingleSourceLocalFilter(
    EventFilter remoteFilter,
    SourceAndType sourceAndType)
{
    var localFilter = new EventFilter(remoteFilter)
    {
        Host = string.Empty,
    };

    localFilter.SourcesAndTypes.Clear();
    localFilter.SourcesAndTypes.Add(sourceAndType);
    return localFilter;
}
```

实际类型名以 CFET2 Core 中 `SourcesAndTypes` 元素类型为准。若该元素类型不是公开类型，可以在实现中用当前列表元素的实际类型替换伪代码中的 `SourceAndType`。

实际实现时，`eventHub.Subscribe(...)` 是过时 API，需要沿用当前代码的 `#pragma warning disable CS0612` 包裹。

`RemoveSubscriberFromKeys(...)` 用于异常回滚和取消订阅的公共清理：

```csharp
private void RemoveSubscriberFromKeys(RemoteSubscriptionKey remoteKey, IEnumerable<ServerSubscriptionKey> keys)
{
    foreach (var key in keys.Distinct())
    {
        if (!aggregatedSubscriptions.TryGetValue(key, out var aggregated))
        {
            continue;
        }

        aggregated.Subscribers.TryRemove(remoteKey, out _);

        if (!aggregated.Subscribers.IsEmpty)
        {
            continue;
        }

        aggregatedSubscriptions.TryRemove(key, out _);

        if (aggregated.LocalToken != null)
        {
            try
            {
                eventHub.Unsubscribe(aggregated.LocalToken);
            }
            catch
            {
                // **重点：这里应记录日志。manager 状态已经清理，不能因为外部 Unsubscribe 异常回滚本地状态。**
            }
        }
    }
}
```

## 7. Manager.Unsubscribe 流程

方法建议：

```csharp
public void Unsubscribe(Guid sessionId, Guid remoteTokenId)
```

处理步骤：

1. 构造 `RemoteSubscriptionKey(sessionId, remoteTokenId)`。
2. 从 `remoteIndex` 找到该远端 token 对应的全部聚合 key。
3. 逐个从聚合项中移除该 subscriber。
4. 如果某个聚合项空了：
   - 从 `aggregatedSubscriptions` 移除聚合项。
   - 调用 `eventHub.Unsubscribe(aggregated.LocalToken)`。

伪代码：

```csharp
public void Unsubscribe(Guid sessionId, Guid remoteTokenId)
{
    var remoteKey = new RemoteSubscriptionKey(sessionId, remoteTokenId);

    lock (syncRoot)
    {
        UnsubscribeCore(remoteKey);
    }
}

private void UnsubscribeCore(RemoteSubscriptionKey remoteKey)
{
    if (!remoteIndex.TryRemove(remoteKey, out var keys))
    {
        return;
    }

    RemoveSubscriberFromKeys(remoteKey, keys);
}
```

## 8. Manager.UnsubscribeSession 流程

session 断开时要清理该 session 下所有远端订阅。

方法建议：

```csharp
public void UnsubscribeSession(Guid sessionId)
```

伪代码：

```csharp
public void UnsubscribeSession(Guid sessionId)
{
    lock (syncRoot)
    {
        var keys = remoteIndex.Keys
            .Where(key => key.SessionId == sessionId)
            .ToArray();

        foreach (var key in keys)
        {
            UnsubscribeCore(key);
        }
    }
}
```

如果不想在 manager 中扫描 `remoteIndex.Keys`，也可以让 `WebSocketSession` 本地维护 `ConcurrentDictionary<Guid, byte> ownedRemoteTokens`，Dispose 时逐个调用 `Unsubscribe(session.Id, tokenId)`。推荐两者都做：

- session 本地 token 表用于高效清理。
- manager 的 `UnsubscribeSession` 作为兜底能力。

## 9. FanOutAsync 流程

本地 EventHub 触发聚合订阅后，manager 需要把事件发送给所有远端订阅者。

伪代码：

```csharp
private async Task FanOutAsync(ServerSubscriptionKey key, EventArg eventArg)
{
    if (!aggregatedSubscriptions.TryGetValue(key, out var aggregated))
    {
        return;
    }

    var subscribers = aggregated.Subscribers.Values.ToArray();

    await Parallel.ForEachAsync(
        subscribers,
        new ParallelOptions { MaxDegreeOfParallelism = maxFanOutConcurrency },
        async (subscriber, cancellationToken) =>
        {
            await subscriber.Session
                .SendRemoteEventAsync(subscriber.RemoteTokenId, eventArg)
                .ConfigureAwait(false);
        }).ConfigureAwait(false);
}
```

发送异常处理建议：

- `SendRemoteEventAsync` 内部捕获发送异常，避免一个断开 session 影响其他 session。
- 如果发送失败且 session 已断开，可以由 session Dispose 负责清理订阅。
- 第一版不建议 fan-out 中直接 unsubscribe，避免并发发送路径和订阅管理路径互相干扰。
- **重点：fan-out 不允许使用无限制 `Task.WhenAll`。建议并发度默认设为 `Environment.ProcessorCount * 2`，或通过 `WebSocketCommunicationOptions` 增加配置项，例如 `MaxFanOutConcurrency`。**

## 10. WebSocketSession 修改点

### 10.1 构造函数注入 manager

当前构造函数：

```csharp
public WebSocketSession(WebSocketCommunicationOptions options, EventHub eventHub, WebSocket socket)
```

修改为：

```csharp
public WebSocketSession(
    WebSocketCommunicationOptions options,
    WebSocketSubscriptionManager subscriptionManager,
    WebSocket socket)
```

`eventHub` 字段可以移除，改为保存：

```csharp
private readonly WebSocketSubscriptionManager subscriptionManager;
private readonly ConcurrentDictionary<Guid, byte> remoteTokens = new();
```

### 10.2 SubscribeAsync 修改

当前 `SubscribeAsync` 直接调用本地 `eventHub.Subscribe(...)`。修改为：

```csharp
private async Task SubscribeAsync(SubscribeMessage message, CancellationToken cancellationToken)
{
    if (message.Filter == null)
    {
        await SendAsync(new SubscribeAckMessage
        {
            TokenId = message.TokenId,
            Accepted = false,
            Reason = "Filter is required.",
        }, cancellationToken).ConfigureAwait(false);
        return;
    }

    try
    {
        // **重点：必须先登记本地 token，再注册 manager。否则断线 Dispose 可能漏清理 manager 中的强引用。**
        remoteTokens[message.TokenId] = 0;
        subscriptionManager.Subscribe(this, message.TokenId, message.Filter);

        await SendAsync(new SubscribeAckMessage
        {
            TokenId = message.TokenId,
            Accepted = true,
        }, cancellationToken).ConfigureAwait(false);
    }
    catch (Exception ex)
    {
        remoteTokens.TryRemove(message.TokenId, out _);
        subscriptionManager.Unsubscribe(Id, message.TokenId);

        await SendAsync(new SubscribeAckMessage
        {
            TokenId = message.TokenId,
            Accepted = false,
            Reason = ex.Message,
        }, cancellationToken).ConfigureAwait(false);
    }
}
```

**重点：`remoteTokens[message.TokenId] = 0` 必须在 `subscriptionManager.Subscribe(...)` 之前执行。**  
原因是 manager 会强引用 `WebSocketSession`。如果先注册 manager，再登记本地 token，中间刚好断线并进入 Dispose，Dispose 可能看不到该 token，从而漏清理 manager 里的 subscriber。失败时必须同时回滚 `remoteTokens` 和 manager。

### 10.3 UnsubscribeAsync 修改

当前 `UnsubscribeAsync` 调用 `UnsubscribeLocal`。修改为：

```csharp
private async Task UnsubscribeAsync(Guid remoteTokenId, CancellationToken cancellationToken)
{
    remoteTokens.TryRemove(remoteTokenId, out _);
    subscriptionManager.Unsubscribe(Id, remoteTokenId);
    await Task.CompletedTask.ConfigureAwait(false);
}
```

### 10.4 Dispose 修改

当前 Dispose 遍历 session 内 `subscriptions.Keys` 调用 `UnsubscribeLocal`。修改为：

```csharp
foreach (var remoteTokenId in remoteTokens.Keys)
{
    subscriptionManager.Unsubscribe(Id, remoteTokenId);
}

remoteTokens.Clear();
```

并且最后必须补一行：

```csharp
subscriptionManager.UnsubscribeSession(Id);
```

**重点：`UnsubscribeSession(Id)` 不能省略。**  
它是 session 本地 token 表遗漏、Subscribe/Dispose 并发、异常中断时的最终兜底，确保 manager 不长期持有已断开 session。

### 10.5 新增 SendRemoteEventAsync

将当前私有 `SendLocalEventAsync(EventArg eventArg)` 改为可被 manager 调用的方法：

```csharp
internal async Task SendRemoteEventAsync(Guid remoteTokenId, EventArg eventArg)
{
    if (disposed || socket.State != WebSocketState.Open)
    {
        return;
    }

    try
    {
        await SendAsync(new RemoteEventMessage
        {
            TokenId = remoteTokenId,
            EventArg = eventArg,
        }, cts.Token).ConfigureAwait(false);
    }
    catch
    {
    }
}
```

是否设置 `TokenId`：

- 当前客户端不依赖 `TokenId` 分发，所以不是必须。
- 建议设置，便于远端日志、排查和未来优化。

**重点：`SendRemoteEventAsync` 不得修改传入的 `EventArg` 实例。**  
当前序列化器是只读序列化，fan-out 可以复用同一个 `EventArg` 对象。若未来要写入 `EventArg.Host`、`Sample.IsRemote`、上下文或其他字段，必须先为每个 subscriber 克隆事件，避免多个并发发送互相污染。

## 11. WebSocketEventServer 修改点

当前 `WebSocketEventServer` 持有 `eventHub`，创建 session 时传入 `eventHub`。

新增字段：

```csharp
private readonly WebSocketSubscriptionManager subscriptionManager;
```

构造函数中创建：

```csharp
this.subscriptionManager = new WebSocketSubscriptionManager(eventHub);
```

创建 session 时改为：

```csharp
var session = new WebSocketSession(options, subscriptionManager, webSocket);
```

Dispose 时：

- 先停止 server。
- Dispose 所有 session。
- session Dispose 会清理 manager 中对应订阅。

manager 必须实现 `IDisposable`，并在 `WebSocketEventServer.Dispose()` 中调用：

```csharp
subscriptionManager.Dispose();
```

manager Dispose 伪代码：

```csharp
public void Dispose()
{
    lock (syncRoot)
    {
        if (disposed)
        {
            return;
        }

        disposed = true;

        foreach (var aggregated in aggregatedSubscriptions.Values)
        {
            if (aggregated.LocalToken == null)
            {
                continue;
            }

            try
            {
                eventHub.Unsubscribe(aggregated.LocalToken);
            }
            catch
            {
                // **重点：这里应记录日志，但 Dispose 不能因单个 Unsubscribe 失败而中断。**
            }
        }

        aggregatedSubscriptions.Clear();
        remoteIndex.Clear();
    }
}
```

**重点：`WebSocketEventServer.Dispose()` 应先 Dispose sessions，再 Dispose manager。**  
session Dispose 会按正常路径清理自身订阅；manager Dispose 是最终兜底，负责释放任何残留的本地 EventHub token。

## 12. 多 SourcesAndTypes 的处理策略

当前 `SubscribeMessage.Filter` 可能携带多个 `SourcesAndTypes`。当前语义是 OR：命中其中任意一个 `SourcesAndTypes` 都要触发该远端 token。因此聚合方案必须原生支持多条规则，不能在服务端拒绝多条 `SourcesAndTypes`。

推荐策略：

1. `Subscribe` 时把一个远端 filter 拆成多条单规则本地订阅。
2. 每条规则生成一个 `ServerSubscriptionKey(Source, EventType, PerformanceLevel)`。
3. 每个 `ServerSubscriptionKey` 最多创建一个本地 `EventHub.Subscribe(...)`。
4. 同一个远端 `(SessionId, TokenId)` 作为 subscriber 加入这些聚合项。
5. `remoteIndex` 保存该远端 token 对应的全部聚合 key：`ConcurrentDictionary<RemoteSubscriptionKey, ServerSubscriptionKey[]>`。
6. `Unsubscribe` 时根据 `remoteIndex` 逐个聚合 key 移除该远端 subscriber。
7. 最后一个 subscriber 离开某个聚合 key 时，释放该 key 对应的本地 EventHub token。

示例：

```text
远端 token T1 filter:
  SourcesAndTypes:
    /a Changed
    /b Changed

manager 创建或复用两个聚合项:
  key(/a, Changed, performanceLevel)
  key(/b, Changed, performanceLevel)

remoteIndex[(sessionId, T1)] = [key(/a...), key(/b...)]
```

事件触发行为：

- 本地 `/a Changed` 事件触发时，fan-out 给 T1。
- 本地 `/b Changed` 事件触发时，也 fan-out 给 T1。
- 如果 T1 取消订阅，则同时从 `/a` 和 `/b` 两个聚合项移除。

重复规则处理：

- 如果同一个 filter 内出现重复的 `Source + EventType + PerformanceLevel`，应通过 `Distinct()` 去重，避免同一个远端 token 在同一个聚合项里重复加入。
- 因为 `Subscribers` 使用 `RemoteSubscriptionKey` 作为 key，即使重复加入也会覆盖同一个 subscriber，但 `remoteIndex` 去重后取消订阅更清晰。

推送去重说明：

- 如果一个事件同时匹配同一个远端 token 的多条规则，例如规则存在重叠正则，当前精确聚合方案可能通过多个聚合项向同一个 token 推送多次。
- 第一版不做跨 key 语义去重，因为这需要理解 EventHub 的完整匹配语义，复杂度和误判风险较高。
- 如果后续必须做单事件单 token 去重，可以在 fan-out 层引入事件级别的临时 `(EventIdentity, RemoteSubscriptionKey)` 去重，但不建议作为第一版范围。

## 13. 正则和重叠订阅说明

如果 EventHub 的 `Source` 支持正则或模式匹配，则：

- `/a/.*` 和 `/a/b` 是两个不同 `ServerSubscriptionKey`。
- 它们会创建两个本地 EventHub 订阅。
- 如果同一个远端 session 同时订阅这两条，某个事件可能被推送两次。

这和原文档结论一致：第一版只做精确 key 聚合，不做正则语义去重。这样性价比最高，也避免误合并导致漏发。

## 14. 并发和生命周期注意事项

### 14.1 Subscribe 与 Unsubscribe 并发

同一 session 的同一 token 可能出现：

- 重复 subscribe。
- subscribe 后立即 unsubscribe。
- session Dispose 与 subscribe 并发。

manager 的 `syncRoot` 必须覆盖：

- `remoteIndex` 更新。
- `aggregatedSubscriptions` 创建。
- 本地 `EventHub.Subscribe/Unsubscribe`。
- 聚合项最后一个 subscriber 判断。

### 14.2 Fan-out 与 Unsubscribe 并发

fan-out 不应长时间持有 `syncRoot`。建议：

1. 从 `aggregatedSubscriptions` 获取聚合项。
2. 快照 `Subscribers.Values.ToArray()`。
3. 释放任何锁。
4. 并发或顺序发送。

这样 unsubscribe 可能与 fan-out 交错。结果是刚取消的订阅可能收到一条已经在途的事件，这是当前 at-most-once/无强一致 ACK 语义下可接受的。

### 14.3 EventArg 是否需要克隆

当前服务端直接把本地 `EventArg` 发给远端。聚合后同一个 `EventArg` 会发送给多个 session。

如果 `WebSocketMessageSerializer.SerializeToUtf8Bytes(...)` 不修改 `EventArg`，可以复用同一个对象。  
如果未来发送前会修改 `EventArg.Host`、`Sample.IsRemote` 或其他字段，则必须给每个 subscriber 克隆事件，避免互相污染。

第一版建议不修改服务端发送的 `EventArg`，保持当前行为。

### 14.4 PerformanceLevel 聚合边界

`ServerSubscriptionKey` 当前包含 `PerformanceLevel`：

```csharp
internal readonly record struct ServerSubscriptionKey(
    string Source,
    string EventType,
    int PerformanceLevel);
```

这样做是保守选择：不同 `PerformanceLevel` 的订阅不会被误合并。

**重点：实现前需要确认本地 `EventHub` 是否允许同一个 `Source + EventType` 使用不同 `PerformanceLevel` 注册多次，并确认这些订阅各自收到事件的语义。**  
如果 `PerformanceLevel` 只影响远端传输负载，而不影响本地 EventHub 匹配，则可以考虑把它从 key 中移除，并在 fan-out 时按 subscriber 的需求处理 payload。但在当前信息不足时，保留在 key 中更安全。

### 14.5 WeakReference 不作为第一版要求

`RemoteSubscriber` 可以直接持有 `WebSocketSession` 强引用。只要做到以下三点，强引用是可控的：

1. `SubscribeAsync` 中先写入 `remoteTokens`，再注册 manager。
2. `WebSocketSession.Dispose()` 中调用 `subscriptionManager.UnsubscribeSession(Id)` 兜底。
3. `WebSocketSubscriptionManager.Dispose()` 中释放所有聚合订阅并清空索引。

**重点：不要用 `WeakReference` 替代正确的生命周期清理。**  
`WeakReference` 可以作为后续极端防漏优化，但第一版不建议引入，避免 fan-out 逻辑复杂化。

## 15. 测试修改建议

新增测试文件建议：

```text
TestCode/WebSocketServerSubscriptionAggregationTests.cs
```

必须覆盖：

1. 多个 session 相同订阅时，本地事件只注册一次。  
   可以通过发布一次本地事件后两个远端都收到，间接验证；更好的方式是构造可计数 EventHub 或通过现有 EventHub 内部状态反射验证。

2. 多个 session 相同订阅时，本地事件 fan-out 给所有 session。

3. 一个 session unsubscribe 后，其他 session 仍能收到事件。

4. 最后一个 session unsubscribe 后，本地 EventHub 订阅被释放，后续事件不再推送。

5. session close 后清理该 session 的聚合订阅。

6. 同一 session 同一 token 重复订阅不同 source 时，旧 source 不再推送，新 source 可以推送。

7. 不同 session 使用相同 `TokenId` 时互不影响。

8. 不同 `Source` 或不同 `EventType` 不会被错误聚合。

9. 多条 `SourcesAndTypes` 必须支持 OR 语义：命中任意一条都应推送给远端 token。

10. 多条 `SourcesAndTypes` 取消订阅时，必须从该 token 对应的所有聚合项移除。

11. 同一个 filter 内重复的 `SourcesAndTypes` 不应导致重复本地订阅或取消订阅异常。

16. `SendRemoteEventAsync` 不修改传入 `EventArg`。如果后续实现改为写事件字段，必须新增 clone 测试。

- `Server_ShouldPushLocalEventToRemoteSubscriber`
- `Server_Unsubscribe_ShouldStopPushForThatToken`
- `Server_SessionClose_ShouldCleanupLocalSubscription`
- `Server_ShouldServeConcurrentSubscribersIndependently`

## 16. 分步落地顺序

建议按以下顺序提交：

1. 新增 manager 和相关 model，不接入现有 session。
2. 增加 fan-out 并发度配置，建议在 `WebSocketCommunicationOptions` 中增加 `MaxFanOutConcurrency`，默认 `Environment.ProcessorCount * 2`。
3. 给 `WebSocketSession` 增加 `SendRemoteEventAsync(Guid, EventArg)`，并保证该方法不修改传入 `EventArg`。
4. 修改 `WebSocketEventServer` 创建并传入 manager。
5. 修改 `WebSocketSession.SubscribeAsync/UnsubscribeAsync/Dispose` 使用 manager，**先登记 `remoteTokens`，Dispose 必须调用 `UnsubscribeSession(Id)`**。
6. 实现 manager 的异常回滚、fan-out 限流和 `IDisposable` 兜底释放。
7. 删除或废弃 `ServerSubscriptionEntry` 和 session 内 `subscriptions` 字段。
8. 补齐聚合相关测试，特别是竞态清理、异常回滚、fan-out 限流和 manager Dispose。
9. 跑 `dotnet test` 验证现有订阅、服务端、心跳重连测试。

## 17. 方案结论

这份修改方案适合当前 WSCM。

它保留了现有协议和客户端行为，只重构服务端接收远端订阅后的本地 EventHub 注册方式。核心收益是把“每个远端订阅一个本地 EventHub 订阅”改成“每个唯一订阅条件一个本地 EventHub 订阅”，可以直接解决相同订阅导致的服务端订阅风暴。

需要特别注意的两个落地点：

1. 反向索引必须使用 `(SessionId, RemoteTokenId)`，不能只用 `RemoteTokenId`。
2. 订阅前必须先清理同 session 同 token 的旧订阅，避免重复订阅改变 filter 时旧聚合项泄漏。
3. 一个远端 token 必须允许映射到多个 `ServerSubscriptionKey`，以保持 `SourcesAndTypes` 的 OR 触发语义。
4. **`SubscribeAsync` 必须先登记 `remoteTokens`，再调用 manager，失败后同时回滚二者。**
5. **fan-out 必须限流，不允许无限制 `Task.WhenAll`。**
6. **manager 必须实现异常回滚和 `IDisposable` 兜底清理。**
7. **`SendRemoteEventAsync` 不得修改共享 `EventArg`；如果要修改，必须先 clone。**
