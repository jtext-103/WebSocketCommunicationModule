## Q0 回包对象隔离

该阶段的功能改动仅为将本次 Echo 保存为局部变量，并直接发布该局部对象；共享 Echo 属性继续显示最新回包。

- 修改前测试：4096 个回包中仅有 1979 个唯一 Seq，缺失 2117 个唯一序号并出现重复。
- 修改后：4096 个不同输入分别对应独立回包，Seq、EventIndex、BucketIndex、SentTimestamp 和载荷对应关系全部通过。
- 独立 4 APP、1000 种事件、10 ms、8 B、往返、5 分钟测试：发布 19,241 次，预期与收到的回包均为 57,723，缺失和重复均为 0，报告 PASS。乱序 9，现有异步回调不保证完成顺序。

## P1 接收数组复用

接收器从 ArrayPool 租借数组，只向 WebSocket 提供配置长度的 ArraySegment，并在异步接收及字符串解码结束后于 finally 归还。首轮保留 MemoryStream 和 ToArray，便于单独判断数组复用效果。

专项验证覆盖脏数组、超出租借长度、分片拒绝排空、取消尚未完成时持有租借、失败与 Close 归还、多连接隔离，以及预热后连续小消息不再固定创建 64 KiB 数组。

- 专项测试：8 项通过。
- WS 全量测试：313 项通过，无失败或跳过。
- 独立接收分配测试：每轮 20,000 条消息，共三轮交替；Q0 均为 66,064 B 每条，P1 约 507 至 511 B 每条。
- 分配数字包含接收函数对测试消息的处理，不包含真实网络和完整 APP 工作负载，不能直接当作整体 CPU 收益。

## 回退方法

以下命令依赖原压测工作区中的阶段副本和 Restore-Stage.ps1。`<工作区根目录>` 需要替换为实际路径；这些副本和脚本不包含在本文档目录中。

各阶段目录的 before、after 和 manifest.json 保存源码副本与 SHA256；Q0 另保存源代码差异。用户已有的 WS 项目引用调整保留在初始副本与补丁中，没有纳入本次业务改动。

先预演相应阶段，再在需要回退时执行。脚本会先核对所有目标文件；若存在阶段之后的新修改，会拒绝覆盖。后续阶段修改同一文件时，按 P3、P2、P1、Q0 的逆序回退。

```powershell
& '<工作区根目录>\newcfet2appbenchmark\artifacts\allocation-implementation-20261019-110802\Restore-Stage.ps1' -Stage P1 -WhatIf
& '<工作区根目录>\newcfet2appbenchmark\artifacts\allocation-implementation-20261019-110802\Restore-Stage.ps1' -Stage P1
```

回退源代码后需要重新编译相应项目；不要使用仍包含后续代码的旧 bin 输出进行验证。各阶段隔离运行包保持冻结，原 benchmark runtime 和服务器 24 小时包保持原样。
