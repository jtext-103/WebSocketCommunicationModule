# WebSocket 分配优化文档

更新日期：2026 年 10 月 19 日。这里整理 P0／Q0、P1、P2、P3 的修改方案、已有测试和性能取舍，供本仓库提交与评审使用。

P1～P3 的产品优化位于 WebSocket 接收器和消息反序列化器；Core 锁结构和接口未修改。Q0 是 Benchmark 的 Echo 并发正确性修复，作为后续比较基线，不属于 WebSocket 产品优化。

## 当前状态

| 阶段 | 变化 | 验证与限制 |
|---|---|---|
| P0／Q0 | 每次 Echo 使用对应的独立回包对象 | 4096 次并发验证通过，冻结正确性基线 |
| P1 | 接收临时数组使用 ArrayPool | 分配显著下降；CPU／延迟的整体稳定收益未证实 |
| P2 | 单帧直接解码，分片移除 ToArray | 21 项接收专项、326 项完整 WS 回归通过，本机阶段完成 |
| P3 | 普通 Context 直接填充最终字典，保留元数据走兼容路径 | 59 项针对性、363 项完整 WS 回归通过；整体性能取舍待确认 |

P3 当前保留。重嵌套固定输入的分配减少与小幅耗时增加均可重复。后续纯分析确认 Status 构造时机提前，但其 GC／CPU 贡献尚未隔离；恢复构造顺序的候选修改没有实施。

## 已有 APP 对照

配置均为 4 APP、1000 种事件、10 ms、8 B、往返模式，各正式发布 5 分钟并完成结算。以下百分比是相对同一行对照版本的变化，不能跨批次直接相加；分钟 P99 中位数不是整轮全局 P99。

| 对照 | 分配速率 | CPU／次发布 | 平均 RTT | 分钟 P99 中位数 |
|---|---:|---:|---:|---:|
| P1 对 Q0，关闭软件后的复测 | −54.3% | +4.2% | +2.4% | −0.2% |
| P2 对 P1 | −4.4% | −24.5% | −10.6% | −3.8% |
| P3 对 P2，先 P3 后 P2 | −1.2% | −9.0% | −7.4% | +3.8% |
| P3 对 P2，先 P2 后 P3 | −0.8% | −1.7% | +2.6% | +1.9% |

所列 APP 对照缺失与重复均为 0。分配收益可以重复，CPU 与 RTT 的改善不能仅凭这些轮次认定为稳定收益；本机结果也不代替服务器 24 小时耐久验证。
