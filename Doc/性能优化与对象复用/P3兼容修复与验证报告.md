## 修复方式

普通 Context 使用原有 JsonSerializer，通过局部 JTokenReader 和 Populate 直接填充预分配的 InvariantCultureIgnoreCase 字典，减少普通临时字典和整表复制。没有逐值手工转换，也没有新增共享 reader、writer 或静态序列化器。

开头为 `$id`、`$ref`、`$type`、`$values`、`$value` 时，沿用修改前完整字典转换及复制路径，保留 Json.NET 的保留元数据与引用作用域。嵌套值在同一 reader 作用域内处理。该兼容分支不承诺分配减少。原失败输入 `{"$id":"context-1","value":1}` 的最终 Context 现与旧实现相同，仅包含 value。

Populate 可能覆盖文化等价键；普通分支通过成员计数差异识别冲突，仅在错误路径重现 Dictionary.Add 的失败分类。保留默认 Status 初始化、旧 objectVal／val 回退、数字和日期类型、原始元数据以及各消息对象独立所有权。Core、比较器、协议和 Benchmark 转换器均未调整。

## 受控分配验证

冻结 P2 与最终 P3 分别在独立加载上下文执行完整同步 DeserializeMessage。七组固定输入先验证键和值的运行时类型及内容一致，再各预热 5,000 次、三轮交替各 20,000 条。下表为三轮每条消息分配量的中位数，包含 JSON 解析及消息对象，不含网络，不等于整套 APP 的分配速率。

| 场景 | P2，B／条 | P3，B／条 | 减少，B／条 |
|---|---:|---:|---:|
| empty | 8,576.34 | 8,502.82 | 73.52 |
| small-scalar | 11,000.44 | 10,536.43 | 464.01 |
| benchmark-nested | 16,584.66 | 16,120.65 | 464.02 |
| nested-heavy-8 | 50,394.02 | 49,401.98 | 992.04 |
| scalar-64 | 40,649.63 | 36,025.45 | 4,624.18 |
| legacy-leading-id | 10,208.41 | 10,208.41 | 0.00 |

所有普通分支场景的分配均下降，开头 `$id` 的兼容路径分配相同。空 Context 首场景存在明显预热／分层编译时间扰动：两版各轮 CPU 并不稳定，不能把其中位数差异当作稳定回退。8 个复杂嵌套字段的场景 CPU 中位数 750→781.25 ms（+4.2%），墙钟中位数约 +6.5%；这属于需保留的成本取舍，不能宣称所有输入都更快。CPU 受进程环境与计时粒度影响，以上用于辅助分析。

## 完整 APP 对照

先 P3 后 P2，各运行 4 APP、1000 种事件、10 ms、8 B、往返、正式发布 5 分钟，并完成相同迟到窗口及结算。相同的 EventCounters、OS CPU 和内存采集；未并行编译或执行额外压测。

| 指标 | P2 | P3 | 变化 |
|---|---:|---:|---:|
| 四 APP 分配速率 | 19.410 MiB/s | 19.185 MiB/s | −1.2% |
| 四 APP CPU／次发布 | 11.453 ms | 10.420 ms | −9.0% |
| 加权平均 RTT | 2.010 ms | 1.862 ms | −7.4% |
| 分钟 P99 中位数 | 5.649 ms | 5.865 ms | +3.8%（约 +0.216 ms） |
| GC 暂停合计速率 | 8.255 ms/s | 6.521 ms/s | −21.0% |
| Monitor 竞争次数 | 10.174 次/s | 11.613 次/s | +14.1% |

P2 发布 19,323 次，收到全部 57,969 个预期回包；P3 发布 19,278 次，收到全部 57,834 个预期回包。缺失与重复均为 0，乱序计数均为 6，最终业务报告均 PASS。现有异步回调不保证完成顺序。

正式阶段 P2 可用内存约 4,820～5,320 MiB，P3 约 4,942～5,455 MiB。P3 的五个分钟 P99 为 6.5271、5.2341、7.1802、5.8650、5.6111 ms；P2 为 5.7085、6.0017、5.3963、5.6486、5.3740 ms。CPU 与平均 RTT 虽下降，尾延迟没有同时改善。Monitor 只有竞争次数，不能据此推断锁等待时间增加或已排除锁问题。

只有一组完整对照，不能宣称上述改善或尾延迟差异可稳定复现，也不能把分钟 P99 中位数称为整轮全局 P99。固定发布间隔下的数据不代表最大吞吐能力。未进行服务器 24 小时耐久验证。
